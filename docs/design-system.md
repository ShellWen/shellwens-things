# ShellWen 设计系统：轻一点，有点俏皮

这是 ShellWen 全站采用的视觉设计系统。它保留大字号 SHELL / WEN、原有手绘小熊与「写点不无聊的代码，有时假装自己是小动物。」的个人表达，以清爽奶白、巧克力棕、浅焦糖和舒展的留白建立现代、轻盈的阅读层级，用圆润形状与局部薄荷和杏桃软底带来一点俏皮。

[打开交互参考页](/design-system) · [首页](/) · [文章列表](/blog) · [关于页](/about)

参考页提供文档内的浅色 / 深色切换、基础规范、组件状态与搜索对话框。它与生产页面共用全局样式与语义组件，不再包含虚构文章的首页、列表与阅读页面样例。

## 1. 设计原则

### 文字先行

标题、段落与留白负责组织内容。先保证信息被读懂，再用排版节奏让人愿意继续阅读。文章标题、日期要各有清晰位置，不用大面积装饰抢占注意力。

### 轻盈，也有秩序

奶白、巧克力棕与浅焦糖构成清爽的浅色基调；深色对应深可可、奶白墨色与浅焦糖。棕色保留个人识别，无衬线排版、轻背景和留白让整体保持现代与灵动。优先用留白和轻背景分组，边界只在需要时出现。重复使用间距与圆角规则，允许内容本身自由变化，正文与页脚保持同一主题。

### 留一点俏皮

品牌大字、手绘小熊和自然的文字语气承担个性。一屏保留一两处小巧思，例如略不对称的柔和色块。小熊不成为每个按钮的图标，强调色不涂满所有卡片；装饰不伪装成控件或在线状态，也不自动运动。

## 2. 使用边界与运行时来源

全站采用同一套设计系统，DaisyUI 依赖、主题和组件类已移除。首页、文章列表、文章正文、关于页、搜索与页脚共用语义色板和基础组件规则。

页面层的解释文案、装饰性小注与虚构文章样例已移除；首页保留原有自述和主要入口，移除底部重复的「翻到文字页」链接。作者撰写的文章、关于页与待办内容继续保留。界面仍保留功能标签、工作状态反馈、无障碍与隐私提示，以及交互限制和必要技术数据。

文章卡片和内容页标题下不再渲染 frontmatter 描述摘要；描述数据仍用于页面元数据与 RSS，文章正文保持原样。

- `src/styles/global.css`：唯一 Tailwind 入口，包含主题、全局基础样式和共享 recipe。
- `src/layouts/BaseLayout.astro` 与 `src/components/BaseHead.astro`：生产页面的 HTML 外框、样式引入、主题同步和页面元数据。
- `src/components/Header.astro`、`HeaderControls.svelte`、`HeaderLink.astro`、`Footer.astro`：共用导航、搜索入口、主题控件与页脚。
- `src/components/home/HomeIntro.astro`、`PostCard.astro`、`GridListSwitcher.svelte`：首页介绍、真实文章条目与列表视图切换。
- `src/layouts/Content.astro`、`Page.astro`、`Post.astro`：文章和普通内容页，统一正文排版、目录与评论入口。
- `src/pages/design-system.astro` 与 `src/components/design-system/Foundations.astro`：同一设计系统的基础规范与组件状态演示。
- 本文：全站视觉规范与样式复用约定。

参考页保留自己的文档导航与 HTML 外框，直接引入同一份 `global.css`，不维护另一份运行时样式。它以 `<html lang="zh-CN" data-theme="light">` 开始，通过根元素的 `data-theme="dark"` 切换配色。参考页的主题按钮只更新当前文档，不写入生产站主题偏好；页面带有 `noindex,nofollow`，不标记为 Pagefind 正文。

生产页面同样只在 `html` 上设置 `data-theme="light"` 或 `data-theme="dark"`。主题偏好继续沿用现有存储标识 `theme=shellwen-light/shellwen-dark` 与 `useSystemTheme`；这些是持久化偏好值，不是 CSS 主题名。系统配色、用户选择和页面导航后的同步由现有主题 store 与布局负责。

组件通过 `var(--color-canvas)`、`var(--color-ink)` 等语义变量引用颜色；字体、圆角和缓动分别使用 `--font-*`、`--radius-*`、`--ease-gentle`。色卡与本文的十六进制值是说明数据，不是第二份运行时主题。动态图片地址和数据色卡背景保留必要的内联值，组件不重新定义调色板。

### 2.1 Tailwind v4 实现约定

`src/styles/global.css` 引入完整 Tailwind，统一使用 theme、preflight 与 utilities；全站类名不加前缀。`@theme static` 定义 20 个语义颜色、两套本地字体栈、四个圆角和缓动变量；`static` 保留动态色卡直接读取的完整主题变量。浅色值在主题中定义，`:root[data-theme='dark']` 覆盖同名颜色变量，`dark:` 也跟随这个根属性。

默认间距基准是 4px，例如 `p-6` 对应 24px。全局 base 层统一字体继承、标题、焦点环、选区、锚点偏移和减少动态效果规则，utility 可以覆盖局部排版。需要边框的元素明确指定宽度与语义颜色，不依赖浏览器默认外观。文章保留 `@tailwindcss/typography` 的正文能力，配合语义变量设置正文、链接、引用和代码等颜色。

### 2.2 用短类名复用样式，用组件复用结构

重复的控件外观使用少量共享 recipe：`button`、`button-primary`、`button-quiet`、`field`、`pill`、`link`、`panel`，以及章节组织所需的 `section`、`section-head`、`eyebrow`、`rule`。基础 recipe 负责尺寸、排印、边界和状态，修饰 recipe 只表达必要差异。主按钮直接写：

```astro
<a class="button button-primary" href="/about">认识一下 ↗</a>
<button class="button button-quiet" type="button">关闭</button>
<label for="email">电子邮箱</label>
<input class="field" id="email" name="email" type="email" />
```

页面外框复用 `page-shell`，图标操作使用 `icon-button`，主题和视图选择使用 `segmented-control`；所有视口的主题选择均保留三个图标按钮，原生弹层使用 `dialog-panel`。禁用状态覆盖悬停和按下反馈；已选中的分段按钮不被悬停底色覆盖；弹层关闭时仍保留原生隐藏行为。

标题、日期和链接一起重复时，复用实际的 `PostCard` 组件；导航、页脚与首页介绍也由自己的组件管理结构和可访问性。组件专属的复杂布局使用短而有含义的局部类名，在组件 `<style>` 中通过 `@reference` 指向 `global.css`，避免把几十个 utility 在多个调用点抄写。一次性的简单布局继续使用 `grid gap-5` 等 utility，不为每个 div 创建包装组件，也不引入通用变体框架。

参考页的组件演示可以用完整的 utility 字符串展示尺寸和关系，但按钮、输入框、标签与生产页面调用同一套 recipe。静态类名必须完整可扫描，例如 `classes: 'text-success bg-success-soft'`；不要按状态动态拼接类名。小熊 mask 和色卡等动态值使用已有主题变量，不增加别名或重复主题。

## 3. 颜色系统

### 3.1 基础与行动色

| CSS token | 浅色 | 深色 | 语义与用途 |
| --- | --- | --- | --- |
| `--color-canvas` | `#FAF8F5` | `#241F1D` | 奶白 / 深可可，页面底色、整体留白 |
| `--color-surface` | `#FFFFFF` | `#302925` | 清透表面，卡片、输入框、局部阅读表面 |
| `--color-soft` | `#F1ECE7` | `#3B322D` | 浅燕麦 / 可可层，次级区域、页脚、代码底色 |
| `--color-ink` | `#3E332E` | `#F5EEE8` | 巧克力 / 奶白墨色，正文、标题、插画 |
| `--color-muted` | `#736259` | `#C4B2A4` | 柔棕灰，摘要、日期、辅助说明；不用透明度模拟 |
| `--color-line` | `#E4DAD2` | `#51443A` | 轻分隔，装饰性线条；不作为唯一控件边界 |
| `--color-control` | `#937D6E` | `#A18A79` | 轮廓，输入框与次要按钮的可识别边界 |
| `--color-accent` | `#865840` | `#DFB493` | 可可棕 / 浅焦糖，主要行动、文字链接、焦点环 |
| `--color-on-accent` | `#FFFFFF` | `#302319` | accent 背景上的按钮文字与图标 |
| `--color-accent-soft` | `#F2E6DC` | `#49382D` | 轻焦糖底，轻量强调区域背景 |

视觉占比建议：约 80% 为页面与表面色，15% 为墨色和分隔，5% 为强调色。它用于判断视觉重心，不是必须逐像素满足的配额。一个主要行动足够突出时，无需把全部链接都做成实心按钮。

深色不是对浅色做反相运算。它使用深可可背景和奶白墨色，让浅焦糖保持清楚的行动层级。不要将原图直接反相；页脚使用当前主题的 canvas 或 soft，与正文自然衔接。

### 3.2 语义状态色

| CSS token | 浅色 | 深色 | 使用方式 |
| --- | --- | --- | --- |
| `--color-success` | `#326D5D` | `#A6DCC7` | 成功文字与图标 |
| `--color-success-soft` | `#E6F3ED` | `#253F3A` | 成功反馈背景 |
| `--color-warning` | `#80601E` | `#EDCF8E` | 提醒文字与图标 |
| `--color-warning-soft` | `#FFF3D6` | `#453C27` | 提醒反馈背景 |
| `--color-danger` | `#A54057` | `#F3AEC0` | 错误文字、图标与错误边界 |
| `--color-danger-soft` | `#FCE9ED` | `#482D3D` | 错误反馈背景 |
| `--color-info` | `#3F668B` | `#ADCEEF` | 补充说明文字与图标 |
| `--color-info-soft` | `#E8F1FA` | `#293D55` | 说明反馈背景 |

每种状态必须同时有明确文字，必要时增加符号。成功写「操作已完成」，错误说明哪里需要修正，不能只让边框变红。文章分类和普通标签使用中性 soft 背景，避免把语义状态色当装饰色。

### 3.3 装饰软底

| CSS token | 浅色 | 深色 | 使用方式 |
| --- | --- | --- | --- |
| `--color-mint` | `#E7F0E5` | `#303F34` | 薄荷，小面积背景形状或小注 |
| `--color-peach` | `#FBE7DC` | `#4A332C` | 杏桃，小面积背景形状或小注 |

以上与基础、行动、状态色共同组成 20 个颜色 token。薄荷和杏桃不具有状态语义，不能代替 success / warning；其上文字统一使用 ink，不使用 muted，以保持一致的强调层级。一处组合不需要同时用完所有装饰色。

### 3.4 对比度与组合边界

以下为指定不透明 sRGB 色值组合的 WCAG 对比度计算结果，数值保留两位小数。它们说明色板配对，不代替真实页面的完整可访问性审计，也不能推出任意两色混搭均通过。

| 前景 / 背景 | 浅色 | 深色 | 对应要求 |
| --- | --- | --- | --- |
| ink / canvas | 11.53:1 | 14.18:1 | 正文与标题 |
| muted / canvas | 5.47:1 | 7.95:1 | 辅助文字 |
| muted / soft | 4.94:1 | 6.10:1 | 次级表面上的辅助文字 |
| muted / accent-soft | 4.73:1 | 5.43:1 | 轻量强调区域上的辅助文字 |
| accent / canvas | 5.69:1 | 8.60:1 | 链接与行动文字 |
| accent / soft | 5.14:1 | 6.60:1 | 次级表面上的链接 |
| on-accent / accent | 6.03:1 | 8.03:1 | 主要按钮文字 |
| control / surface | 3.89:1 | 4.37:1 | 非文字控件边界 |
| control / canvas | 3.67:1 | 4.99:1 | 页面底色上的控件边界 |
| control / soft | 3.31:1 | 3.83:1 | 次级表面上的控件边界 |
| ink / mint | 10.47:1 | 9.69:1 | 薄荷装饰软底上的文字 |
| ink / peach | 10.23:1 | 10.15:1 | 杏桃装饰软底上的文字 |
| 各状态文字 / 对应状态 soft | ≥ 5.19:1 | ≥ 6.77:1 | 成对使用的反馈信息 |

普通文字采用至少 4.5:1，必要控件边界与非文字识别信息采用至少 3:1。装饰性 `line` 不承担上述控件识别职责。重要文字不用整体透明度削弱，否则需重新计算实际混合后的颜色。

## 4. 字体与排版

### 4.1 字体栈

| CSS token | 完整字体栈 | 使用范围 |
| --- | --- | --- |
| `--font-sans` | `Inter, "Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif` | 导航、界面、标题、正文、副标题与引语 |
| `--font-mono` | `"JetBrains Mono", "SFMono-Regular", Consolas, monospace` | 代码、日期、标识符与索引 |

这些是本地回退建议，不是已经内置或加载的字体。浏览器按照本机可用字体逐字回退，因此拉丁字母与汉字可能来自不同字体，实际字形、字宽与可用字重取决于操作系统。未安装 Inter 或 Noto 字体时，不会自动下载。未来若要统一字形，应另行评估中文字体体积、字形覆盖和加载策略；当前实现不增加网络字体或字体依赖。

### 4.2 字级

| 层级 | 字号 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| Display | `clamp(64px, 8vw, 112px)` | `.98` | `800` | SHELL / WEN 拉丁品牌字 |
| H1 | `36–56px` 流式 | `1.2` | `700` | 页面唯一主标题 |
| H2 | `28–36px` 流式 | `1.3` | `650` | 主要章节 |
| H3 | `20–24px` 流式 | `1.45` | `600` | 分组与文章小节 |
| Body | `16px` | `1.8` | `400` | 界面正文 |
| Article | `18px` | `1.9` | `400` | 长文阅读 |
| Small | `14px` | `1.6` | `400` | 控件文字、摘要、辅助说明 |
| Micro | `12px` | `1.5` | `400` | 非关键日期、索引、色值元数据 |

Display 字距为 `-.055em`，仅适用于拉丁品牌字；中文标题保持自然字距，最多收紧到 `-.01em`，正文保持自然字距。不对中文使用 uppercase 或拉开的全大写风格。重要说明、错误信息与操作标签不得降到 12px。等宽字体不承载长段中文，章节索引也无需全部使用醒目的大写技术标签。

副标题采用无衬线 `24px / 1.65`、字重 `500`，引语采用无衬线 `24px / 1.7`、字重 `500`。用字重、间距和浅焦糖色内嵌底表达语气，避免夸张的引号装饰；页尾题记也沿用无衬线字体。

正文行宽上限 45rem，实际文章容器上限 720px；18px 中文约每行 40 字。窄屏以内边距后的可用宽度为准。段落靠间距分隔，不用连续空行或额外 `<br>` 充当布局工具。

中文与英文混排要同时检查，例如「关于代码，也关于生活。A small corner of the internet.」；不能只用英文 pangram 评估中文阅读效果。品牌字以两行大字与 ink / accent 轻色差形成节奏，正文与功能标签使用清楚的实心字形。

## 5. 空间、布局与形状

### 5.1 间距尺度

以 4px 为基准，使用 `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96px`。

- 4–12px：标签与图标、标题与补充信息、控件内部。
- 16–32px：卡片内边距、相关组件之间、内容行之间。
- 48–96px：内容组、主要章节与页面上下留白。

这些数值是空间尺度，不表示每个值都有一个独立导出的 CSS 变量；实际公共变量以中央样式文件为准。相同语义关系使用相同距离，避免逐个页面累积任意数值。

### 5.2 页面栅格

| 视口 | 栏数 | 页面水平边距 | 栅格间距 |
| --- | --- | --- | --- |
| 手机 `<640px` | 4 | 20px | 24px |
| 平板 `640–1023px` | 8 | 24px | 24px |
| 桌面 `≥1024px` | 12 | 32px | 24px |

普通页面内容最大宽度 1120px，文章阅读最大宽度 720px，均居中且不超过可用宽度。首页在 768px 及以上采用品牌文字与插画两列，在此之下单列排列；这个组合断点独立于总体栅格断点。

参考文档自身的外框最大宽度为 1440px，与生产页面宽度分开：1200px 及以上为 176px 侧栏、48px 栏间距；1024–1199px 为 152px 侧栏、32px 栏间距；小于 1024px 改为单列与可局部横向滚动的章节导航。Tailwind 实现保留 640 / 768 / 1024 / 1200px 断点，其中 1200px 使用任意断点，不替换为默认 1280px 的 `xl`。

手机（`<640px`）导航为完整两行，总高 108px：品牌与主题 / 搜索工具占 56px，三个文字导航占 44px，底部留 8px；整个页头以 `top: 0` 吸顶，滚动时不自动收起。导航链接按内容宽度排列，约 60px 宽、至少 44px 高，整体居中、间距 16px，不平分整行。手机主题按钮组在所有手机宽度统一为透明的 132×44px 区域，`gap` 与内边距均为 0；图标为 16px，外显圆形为 32px，每个按钮仍保留 44×44px 命中区域。`≤359px` 时品牌字号为 16px。不要依靠无规则的 flex 换行让品牌、工具与文字散落。带 id 的锚点使用手机 124px、桌面（`≥640px`）104px 的 `scroll-margin-top`。参考页的章节导航可以横向滚动，但滚动限定在导航自身，不撑宽整页。页脚可用同一主题的 canvas 或 soft，沿用同一内容宽度与水平边距。

长 URL 使用 `overflow-wrap: anywhere`。代码块保留代码结构，在自身容器 `overflow-x: auto`；宽表格同样在自身容器横向滚动，保留表头与语义。阅读区、栅格子项和弹层内容需要允许收缩（例如 `min-width: 0`）。普通正文不能通过整页横向滚动才能读完。

### 5.3 形状、边界与图标

| CSS token | 圆角 | 使用范围 |
| --- | --- | --- |
| `--radius-control` | `10px` | 输入框、按钮 |
| `--radius-panel` | `20px` | 卡片、面板与内容容器 |
| `--radius-frame` | `24px` | 大型页面样例 |
| `--radius-tag` | `999px` | 标签、状态与紧凑的选中导航 / 主题分段 |

- 圆角使用中央样式的 token，不把全部标题、内容或导航都胶囊化。
- 边界最多 1px；输入框和次要按钮使用 control，装饰分隔使用 line。
- 先用留白与轻背景分组；line 只在需要澄清关系时出现，不为每段文字画框，也不伪装为输入边界。
- 所有可见交互控件：至少 44px 高，触控与图标按钮提供至少 44×44px 命中区域。
- 图标：桌面常规 20px；手机主题按钮图标 16px，按钮的外显圆形为 32px、命中区域为 44×44px；搜索图标沿用现有尺寸，线宽 1.75；带可见标签，纯图标按钮必须有明确 `aria-label`。

常规卡片不使用投影。确需浮层层级时，只保留一处小而柔和的阴影，不把阴影当作每个模块的默认装饰。具体浮层阴影值以中央样式为准。

## 6. 品牌与插画

品牌组合由 SHELL / WEN 拉丁大字、中文「颉文」、原有手绘小熊与一句自我介绍构成。首页以两行大字和 ink / accent 轻色差形成层次；紧凑导航只保留清楚的文字标识。

插画来源为 `src/assets/images/home_front.png`。参考页复用现有 `getImage` 的 WebP 转换方式，再以完整图像作为 CSS mask，使用 `var(--color-ink)` 着色。蒙版改变着色方式，不改变原始轮廓。

保留原图比例 `929 / 1693`，使用 contain，不拉伸、不裁掉脸部、不随主题直接反相原图。常规插画建议高 120–240px，首页可更大；周围至少保留 24px 空白。可以在身后放小面积、略不对称的圆润软底，避免巨大的整块椭圆背景、渐变与发光效果。

有信息价值的独立插画需要文字替代；相邻说明已完整描述同一内容时，插画用 `aria-hidden="true"` 避免重复朗读。插画用于首页、关于页或有意义的空状态，不重复附着在每张文章卡和每个按钮上。

每个组合限制一两处小细节，例如品牌旁的小色点或柔和色块，不逐项堆叠。正文始终端正。简单四角星等纯装饰使用 `aria-hidden="true"`，不显示手形光标，不冒充按钮或在线状态。

## 7. 组件与交互规则

### 按钮、链接与标签

主要按钮用 accent / on-accent，一组操作中优先只有一个视觉主动作。次要按钮使用 surface 与 control；轻量操作使用安静的文字形式。链接保留可见下划线或同等清晰的链接线索，不只在悬停时显露身份。页面导航使用链接，执行动作使用按钮，不把按钮嵌进链接。

默认、hover、focus-visible、active 与 disabled 都有明确用途。悬停只增强反馈，不能成为发现交互的唯一方式。禁用使用原生 `disabled` 语义并保留可辨认文字，不仅调低透明度。标签用于分类，状态标签必须同时写出含义。

### 输入与表单

每个输入有真正关联的 label，说明必填 / 可选；placeholder 不替代标签。辅助文字与错误提示通过 `aria-describedby` 关联，错误时设置 `aria-invalid`。错误说明修复方向，成功反馈说明真实发生的动作。状态更新在合适的 `aria-live` 区域播报，避免重复或过度打断。

参考页的邮箱表单只校验文本格式，不注册、不发送数据、不暗示后端成功。空值必须提示必填；格式有效时明确说明「文本格式有效；这是组件演示，不会发送数据」。演示动作使用「校验示例」，不使用容易被误认为真实订阅的文案。HTML 中的 `#ds-validate` 默认禁用，仅在表单处理器初始化后启用，避免脚本未就绪时发生原生提交。

### 搜索与对话框

现有站点有搜索入口，因此搜索作为本设计系统的一等交互模式。

- 对话框最大宽度 640px；手机保留左右各 20px 空间，内部 padding 为 20px，内容随可用宽度收缩；输入等表单控件使用 16px 字号。
- 使用原生 `<dialog>` 与 `showModal()`，提供可见标题、明确的关闭按钮和可访问名称。
- 打开后焦点进入搜索输入；模态期间焦点留在对话框内，即使输入已有内容，按一次 Escape 也应关闭。点击遮罩或关闭按钮同样关闭，关闭后焦点返回触发搜索的控件。
- 输入框有真实标签；搜索与关闭按钮至少 44×44px，结果链接也保持足够点击高度。
- 加载状态用「正在搜索」等文字，空结果说明没有找到并建议调整关键词，错误说明检索失败和可采取的动作。不能只改变颜色或显示无名称的转圈图标。
- 结果显示可理解的标题、摘要或路径；键盘用户能逐项访问。手机结果列表最大高度为 `min(480px, max(120px, calc(100dvh - 304px)))`，在对话框内部滚动，不遮住关闭入口。

参考页明确标记「演示索引 · 3 篇」，只在本地筛选三个真实文章链接的标题，不请求全站内容索引或后端。同步本地筛选无需制造假加载或假网络错误；上述加载 / 错误规则适用于真实搜索集成。

### 展开内容与分页

补充说明可使用原生 details / summary，展开状态需明确且能用键盘操作。分页若只是视觉规范必须标记为样本；实际链接必须有明确目标，当前页用适当语义表达，不放无行为的 `href="#"`。不为示例加入无实际结果的点赞、收藏或假搜索按钮。

文章目录使用原生 `<details>` / `<summary>`，summary 与目录链接的触控目标至少 44px 高。手机（`<640px`）默认收起，桌面（`≥640px`）默认展开；跨越断点时同步展开状态，断点内允许用户自行切换，键盘行为沿用浏览器原生实现。

## 8. 动效

即时交互反馈使用 140ms，面板显隐使用 220ms；缓动为 `cubic-bezier(.2,.7,.2,1)`。以颜色、边界、透明度的轻量变化为主；链接箭头可在悬停时轻移 2px，文字和整块内容保持稳定。不使用缩放、弹跳、自动播放、持续循环或视差来吸引注意力。

尊重 `prefers-reduced-motion: reduce`，移除过渡和平滑滚动，不只是把动效缩短到仍会闪动的极小值。交互状态不能依赖动画结束才能理解。锚点设置 `scroll-margin-top`，避免被固定导航遮挡。

## 9. 无障碍与内容适应

- 页面语言为 `zh-CN`；每页一个 h1，标题层级体现结构，不为外观跳级。
- 页面提供清晰的 header、nav、main 与 footer 结构；章节链接与标题对应。
- 键盘可以到达所有操作，focus-visible 使用 accent 焦点环，与控件留出 3px 偏移，不能被裁切。
- 所有视口均使用三个主题图标按钮，通过可访问名称区分「跟随系统 / 浅色 / 深色」，通过 `aria-pressed` 表示当前状态，不能仅依靠视觉底色；保留系统主题跟随、偏好持久化与页面导航后的同步。
- 不依赖颜色传达错误、成功、选中与链接身份；图标和插画有适当名称或装饰性隐藏。
- 文字和控件遵循第 3 节配对对比度；disabled 的特殊表现不应削弱正常说明的可读性。
- 320 / 360 / 390 / 639px 手机宽度下，卡片与表格内容仍可理解；在 359 / 360px 边界检查品牌与主题按钮组的紧凑布局（手机主题组为透明 132×44px、`gap` / 内边距为 0，图标 16px、外显圆形 32px、命中区域 44×44px），在 639 / 640px 边界检查页头布局与目录状态切换；各视口均保留三个主题图标按钮，阅读顺序与 DOM 顺序一致。
- 放大文字与页面缩放后，内容可重排，长内容不被固定高度裁掉。代码、宽表格与章节导航可局部滚动，页面本身不横向溢出。
- 用户减少动态效果的偏好覆盖页面装饰和交互过渡。

这些是设计与实现要求。调色板计算结果不代表已经完成辅助技术测试；实际页面仍需键盘、缩放、窄屏和读屏检查。

## 10. 页面模式

### 首页

大字 SHELL / WEN 建立第一印象，干净的无衬线副标题保留原有简短自述「写点不无聊的代码，有时假装自己是小动物」，小熊以完整轮廓和局部柔色背景形成视觉平衡；副标题可轻轻强调一个短语。主要行动指向「关于我」，文章入口保持清楚但不过度竞争。手机将双列合并，保留完整品牌名和插画，收紧区块间距并将小熊高度缩为 140px，避免用强制缩放挤进同一行。

### 文章列表
